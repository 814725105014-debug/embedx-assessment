# CAMS Apps Script Replacement Guide — Direct Firebase QR & Verification

## Why QR Codes Previously Had `/macros/u/5/s/.../exec`
1. `Settings -> QR Verification Base URL` pointed to `https://script.google.com/macros/s/.../exec`.
2. When `syncVerificationUrlSetting()` was run while signed into multiple Google accounts (`/u/5/`) on Chrome, `ScriptApp.getService().getUrl()` returned `https://script.google.com/macros/u/5/s/.../exec`.
3. When any phone signed into multiple Google accounts opened `script.google.com/macros/s/...`, Chrome rewrote the URL to `/macros/u/5/s/...`, which Google Workspace (`@trp.srmtrichy.edu.in`) rejects unless rewritten to `/a/macros/trp.srmtrichy.edu.in/...` AND signed into an institutional account.

## How This Fix Solves It Permanently
- **QR codes now encode the direct Firebase URL ONLY**:
  `https://embedx-assessment.web.app/verify?certificateId=EEE%2FEMBX-2026-0004`
- **Verification renders 100% natively on Firebase (`/verify`)** — **NO redirect** to Google Apps Script, no institutional sign-in wall, and no `/u/5/` multi-account bug.
- **Automatic Cloud Sync**: Every certificate generated by CAMS (from the Quiz Website, Google Forms, or `generateAllPending`) automatically syncs its public verification record directly to Firebase Cloud Firestore (`certificates/{certKey}`).

## Step-by-Step: Exact Files to Replace in Google Apps Script

Open your CAMS Google Form → **⋮ (top-right)** → **Script editor**, then update these **4 files**:

| # | File in Apps Script | Action | Exact Change Summary |
|---|---|---|---|
| **1** | **`QRManager.gs`** | **REPLACE entire file** (or replace `buildQrPayload_` + `normalizeQrBaseUrl_` at the top) | Sets `CAMS_FIREBASE_VERIFY_URL = 'https://embedx-assessment.web.app/verify'` and blocks any `script.google.com` link from ever entering a QR code. |
| **2** | **`Verification.gs`** | **REPLACE entire file** | Updates `syncVerificationUrlSetting()` to write `https://embedx-assessment.web.app/verify` (never `/macros/u/5/`), and adds `?format=json&certificateId=...` JSON API support for silent background lookup. |
| **3** | **`Certificate.gs`** | **REPLACE entire file** | Trims any trailing `/` from `Certificate Prefix` (preventing `EEE/EMBX/-2026-...`) and automatically calls `syncRowCertificateToFirebase_(sheet, row)` right after `Mail Status = Sent`. |
| **4** | **`QuizWebhook.gs`** | **ADD new Script file** named `QuizWebhook` (or replace if already added) | Adds `doPost(e)` for Quiz Website auto-certificates (including `Mobile Number` & `Year of Study` columns), Firestore REST API sync (`syncRowCertificateToFirebase_`), and 1-click `syncAllCertificatesToFirebase()`. |

### Final Deployment Step in Apps Script (30 Seconds)
1. Press **Ctrl + S** to save all files.
2. Click **Deploy** (top-right) → **Manage deployments** → click the **Pencil (Edit)** icon → **Version: New version** → **Who has access: Anyone** → **Deploy**.
3. *(Optional backfill)* If you ever have existing `Sent` rows in `'Form Responses 1'`, select **`syncAllCertificatesToFirebase`** in the toolbar dropdown and click **Run** once.

## Firestore access and deployment prerequisites

Certificate registry writes must be authenticated. In `appsscript.json`, add `https://www.googleapis.com/auth/datastore` to the existing `oauthScopes` array (keep all existing scopes). Authorize the script again when prompted. The Google account executing the web app and the account running backfill must have an appropriate Firestore IAM role (for example Cloud Datastore User) on `embedx-assessment`. The sync uses that account's OAuth token; an API key alone is not authorization. Check Apps Script execution logs for sync errors.

Deploy BOTH Hosting and Firestore rules with the Firebase CLI: `firebase deploy --only hosting,firestore:rules --project embedx-assessment`. The GitHub workflow deploys Hosting only when its service-account secret is configured; pushing to GitHub does not by itself deploy rules. Verify with a new certificate and on a separate device. Existing PDF QR codes cannot be changed retroactively; regenerate/reissue them if they contain the old URL.

Security note: the quiz webhook secret is present in browser-delivered code and is not a real secret. Do not rely on it to authorize certificate issuance. Protect issuance with a trusted backend and server-side credentials before production use.
